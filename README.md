# 志望動機メーカー

高校生が、卒業後の進路に向けた**志望動機**を自分の言葉でまとめられるWebアプリです。
**最初に「進学」か「就職」かを選ぶと、そこから先の質問・文章の型・チェック項目がすべて切り替わります。**
回答結果は Google Apps Script 経由で Google スプレッドシートに1人1行で集まります。

```
進路をえらぶ → 型をえらぶ → 質問に答える → 下書きが組み上がる → 自動で見直す → 先生に提出
  STEP 0       STEP 1       STEP 2〜5      STEP 6            STEP 7       STEP 8
```

**質問より先に、文章の型を決めます。** 3つの質問に答えると6つの構成から1つが決まり、
そのあとの設問は、選んだ型が必要とするものだけになります。
聞かれたことは全部本文に使われるので、答えた材料が余りません。

## いちばんの特徴：魅力カード

「魅力を感じた点」をチップで選ばせると、押した人全員が同じ一文になります。
そこで本アプリは、魅力を **①どこで ②何を見た・聞いた ③どう感じた ④自分の何とつながる**
の4つに分けて、1枚ずつのカードとして書いてもらいます（最大3枚、★で重みづけ）。

```
① 体験授業
② 学生同士が、答えではなく考え方のほうを話し合っていた
③ [わくわくした] [自分もやってみたい]
④ 課題研究で、人と話すほど自分の考えが整理された経験と重なります
        ↓ そのまま本文へ
体験授業を受けたとき、学生同士が、答えではなく考え方のほうを話し合っていたのが
印象に残りました。そのとき私はわくわくし、自分もやってみたいと思いました。
課題研究で、人と話すほど自分の考えが整理された経験と重なります。
```

単語の穴埋めしかしていないのに、**その生徒しか書けない文**ができます。
入力中は「この文になります」プレビューがリアルタイムで出ます。
設計の詳細は [docs/04_ATTRACTION_CARD.md](docs/04_ATTRACTION_CARD.md)。

## 進学と就職で、何が変わるか

| | 🎓 進学（大学・短大・専門学校） | 💼 就職（企業・公務員） |
|---|---|---|
| 中心に置く問い | そこで**何を学びたいか** | そこで**どう働きたいか** |
| STEP 4 のタイトル | 学校を知る | 会社を知る |
| 調べる対象 | カリキュラム・ゼミ・実習・資格 | 事業内容・製品・技術・理念 |
| きっかけの選択肢 | オープンキャンパス／体験授業／進学ガイダンス | 求人票／会社説明会／職場見学／インターン |
| 専用の設問 | 特に学びたい授業 | 仕事の理解／自分が活かせる力 |
| 敬称 | 貴校 | 貴社 |
| 目標字数の初期値 | 500字 | 300字 |
| 専用の自動チェック | — | 待遇・条件だけが理由になっていないか |
| 魅力カードの「場面」 | オープンキャンパス／体験授業/学園祭 など | 職場見学／会社説明会／求人票 など |

目標字数は、STEP 1 で長さを選んだ場合はそちらが優先されます。

進路を選び直すと、選択肢の中身がちがう設問だけが白紙に戻ります（確認ダイアログあり）。
名前や志望先など共通の入力は残ります。

## 特徴

| 機能 | 内容 |
|---|---|
| **進路で切り替わる8ステップ** | 進学／就職を選ぶと、設問・生成文・チェック項目が入れ替わる |
| **型を先に決める** | 3つの質問で構成を判定。その型に必要な設問だけを出すので、材料が余らない |
| **なぜなぜ深掘り** | 「なぜ？」を3回くり返し、その人にしか書けない動機まで降りていく |
| **答えるのは単語だけ** | 記述欄をなくし、選択肢と単語で回答。助詞・動詞・語尾はアプリが組み立てる |
| **こう文になります** | 入力したそばから、その言葉が本文でどんな一文になるかを表示する |
| **書き方の例と注意** | 設問ごとに「こんな書き方」を2〜4個と、よくある失敗を1行で示す |
| **設問のグループ分け** | 同じ話題の設問を囲みでまとめ、番号と見出しをつける |
| **進み具合の表示** | 「答えた質問 5 / 12問（必須があと1問）」をステップの上に出す |
| **説明をたためる** | 慣れたら「説明をたたむ」で、質問と入力欄だけの画面にできる |
| **選べる個数の上限** | 設問ごとに上限を決め、達したら選べなくする（本文に入る数と合わせる） |
| **記述欄の字数上限** | 欄ごとに上限を決め、残り字数を表示。長い文が入って文が壊れるのを防ぐ |
| **前の答えの引用** | 「それは」「その活動で」が何を指すのか、前の答えを設問の上に出す |
| **2回目からは貴校・貴社** | 志望先名の繰り返しを自動で敬称に置きかえ、本物の志望理由書の文体に近づける |
| **語尾の言いかえ** | 「〜と考えています」が続いたら、意味を変えずに別の言い方へ |
| **魅力カード** | 場面・感情・接続を分けて書くと、そのまま自分だけの文章になる |
| **6つの構成テンプレート** | 場面描写型／結論先行型／エピソード型／将来目標型／成長課題型／三つの理由型 |
| **構成のおすすめ判定** | STEP 1 の3問から向いている型を判定し、理由つきで提案する（変更も自由） |
| **使われていない材料の表示** | 字数調整で削られた材料を一覧で知らせる |
| **字数の自動調整** | 目標字数を超えないよう、影響が最小の文から自動で削る |
| **文体の一括変換** | です・ます調 ⇄ だ・である調（動詞の活用表で変換するため誤変換が起きにくい） |
| **自動セルフチェック15項目** | 字数・文体の混在・話し言葉・具体性・使い回し表現・見てきたことの反映など |
| **自動保存** | localStorage に保存。途中でブラウザを閉じても続きから再開できる |
| **提出方法いろいろ** | スプレッドシート送信／テキスト保存／コピー／印刷 |
| **進路で色が変わるUI** | 進学＝藍／就職＝深い青緑。アプリ全体のアクセント色が切り替わる |
| **ダークモード対応** | 端末の設定に追従。印刷用のレイアウトも別に用意 |
| **サーバー費用ゼロ** | 静的ファイル＋GAS のみ。GitHub Pages で公開できる |

## 使い方（生徒）

1. アプリを開き、**進学か就職かを選ぶ**
2. STEP 1 で**文章の型をえらぶ**（3問に答えるだけ。向いている型が理由つきで出ます）
3. STEP 2〜5 の質問に答える（**単語だけでOK**。文末は気にしなくて構いません）
   - STEP 4 の**魅力カード**がいちばん大事。見学や説明会で心が動いた場面を書く
4. STEP 6 で下書きができるので手直しする（型はここからでも選び直せます）
5. STEP 7 の自動チェックで赤い項目を直す
6. STEP 8 で送信・印刷する

```
① スプレッドシートを作る
```

**送信先を設定しなくても、下書き作成・チェック・印刷・コピーはそのまま使えます。**

## ファイル構成

```

config.js               ★ 設定はここだけ（GASのURL・合言葉）
assets/
  css/style.css         デザインシステム（トークン・進路別テーマ・ダーク・印刷）
  js/
    questions.js        設問定義。buildSteps(進路, 型) が設問を出し分ける

    compose.js          下書き生成（6テンプレート・語彙表・字数調整・文体変換）
    checklist.js        自動セルフチェック15項目
    api.js              GASへの送信
    app.js              画面制御（進路選択・ステップ進行・保存・描画）
gas/
  Code.gs               ★ Apps Script に貼り付けるコード
docs/                   構想・調査・手順書
```

## カスタマイズ

### 質問を足す・変える
`assets/js/questions.js` の `buildSteps(mode, template)` を編集します。`mode` は `'shingaku'`（進学）か `'shushoku'`（就職）。
進路で文言だけ変えたいときは `job ? 'こっち' : 'あっち'` の形で書き分けます。
**特定の型のときだけ出したい設問**には `only: ['future', 'gap']` のように型IDを書きます（省略すると全部の型で出ます）。
設問を1つ足したら、`assets/js/app.js` の `payload()` と `gas/Code.gs` の `COLUMNS` に
同じキーを足すと、スプレッドシートにも列が増えます。

### 進路を増やす（例：公務員・海外進学）
`questions.js` の `COURSES` に項目を足し、`compose.js` の `LEX`（語彙表）に対応する呼び方を追加します。
`buildSteps` の分岐を増やせば、設問も切り替わります。

### チェック項目を変える
`assets/js/checklist.js` の `SPOKEN`（話し言葉）、`NEGATIVE_SHUSHOKU` / `NEGATIVE_SHINGAKU`、
`CONDITION_ONLY`（待遇語）、`CLICHE_COMMON`（使い回し表現）などの配列に語を追加するだけで
判定に反映されます。

### 型の判定を変える
`assets/js/questions.js` の `PICKER`（3つの質問）を編集します。
各選択肢の `vote: { scene: 2 }` が型への投票、`TIE_BREAK` が同点のときの優先順です。
長さの質問だけは `chars` も持っていて、そのまま目標字数になります。

### 構成テンプレートを足す
`assets/js/compose.js` の `TEMPLATES` に1件足し、`build` 関数を書きます。
新しい型を `PICKER` のどれかの選択肢に投票させると、判定にも乗ります。
各文は `S('文', 優先度)` で作り、優先度は **0=骨組み（絶対に消さない）／1=必須／2=推奨／3=余裕があれば**。
書き出しと結びを 0 にしておけば、字数をどれだけ詰めても文章として成立します。

### 設問の説明や例を変える
`assets/js/questions.js` の各設問が持つ 4 つの項目を編集します。

| キー | 画面での見え方 |
|---|---|
| `hint` | 質問の下の小さな説明 |
| `examples` | 「こんな書き方」の破線チップ（押せません） |
| `avoid` | 「注意」の1行 |
| `preview` | 「こう文になります」。回答全体を受け取って1文を返す関数 |
| `refer` | 設問の上に出す引用。「▸ 「〇〇」について」の形で、指す先を示す |
| `group` | どのグループの囲みに入れるか。グループ自体はステップの `groups` で定義 |
| `max` | チップで選べる個数の上限 |
| `maxChars` | 記述欄の字数の上限 |

`preview` は生成側とまったく同じ枠を書きます。枠を変えるときは
`compose.js` の対応する関数と両方直してください。

### 魅力カードの選択肢を変える
`assets/js/questions.js` の `WHERE_SHINGAKU` / `WHERE_SHUSHOKU`（場面）と `FEELINGS`（感情）。
場面には文の書き出し（`lead`）を、感情には文中形（`te`）と文末形（`end`）を持たせています。

## 動作環境

- モダンブラウザ（Chrome / Edge / Safari / Firefox）
- ビルド不要。`index.html` をブラウザで開くだけで動作します
  （`file://` でも動きますが、送信機能を使うときは GitHub Pages などのHTTPS配信を推奨）

## 注意

- 入力内容はブラウザの localStorage に保存されます。**共用パソコンでは、終わったら「最初からやり直す」を押してください。**
- 合言葉（`SHARED_TOKEN`）は公開すると誰でも見られます。いたずら投稿を減らす程度のものと考え、
  住所・電話番号などの個人情報を入力させる設問は追加しないでください。
