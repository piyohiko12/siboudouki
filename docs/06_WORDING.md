# 設問のかたちと、日本語の自然さ

## 1. 何が起きていたか

生徒が書いた文を、そのまま枠にはめ込んでいた。

```
設問: 「将来やってみたい仕事」   回答: 「看護師になりたい」
枠:   「私は将来、{回答}を目指しています。」
        ↓
出力: 「私は将来、看護師になりたいを目指しています。」   ← 非文
```

枠は1つなのに、生徒の答えの形は人それぞれ。
名詞で書く子、文で書く子、常体で書く子、敬体で書く子。
**どんな形で来るか分からないものを、決まった枠にはめれば必ず壊れる。**

## 2. 直し方：生徒は名詞だけ、文法はアプリが持つ

考え方を逆にした。

```
生徒が答えるもの   単語・名詞のかたまり（「看護師」）
アプリが持つもの   助詞・動詞・語尾（「私は将来、〜になりたいと考えています。」）
```

さらに、**選択肢で決められるものは全部選択肢にした**。
選択肢には「その語を文にどう組み込むか」の型を持たせてある。

```js
{ label: 'なりたい職業がある', frame: '私は将来、{X}になりたいと考えています。' }
{ label: '興味のある分野がある', frame: '私は将来、{X}の分野に進みたいと考えています。' }
{ label: 'まだ決まっていない', frame: '将来の進路はまだはっきり決めていませんが、{X}に強い関心があります。' }
```

生徒は「なりたい職業がある」を選び、「看護師」と書くだけ。
出力は「私は将来、看護師になりたいと考えています。」になる。**壊れようがない。**

## 3. 設問の内訳

型によって出る設問が変わるので、問数も型ごとに違う。

| 型 | 進学 | 就職 |
|---|---|---|
| 場面描写型 | 40問 | 40問 |
| 結論先行型 | 44問 | 44問 |
| エピソード型 | 43問 | 43問 |
| 将来目標型 | 43問 | 43問 |
| 成長課題型 | 42問 | 42問 |
| 三つの理由型 | 44問 | 44問 |

どの型でも、内訳は「選択式 17〜19問／単語で答える 19〜23問／長い記述 **0問**」。
（型ごとの出し分けは §18、ステップの並びと追加した設問は §19）

長い記述欄は全廃した。唯一「魅力カードの②（何を見た・聞いた）」だけは
観察をそのまま書いてもらうが、ここは語尾を常体にそろえてから
「〜のが印象に残りました」という枠にはめるので、どう書かれても文になる。

## 4. 選択肢を持つ設問（型つき）

| 設問 | 選択肢の例 | 組み込まれ方 |
|---|---|---|
| いつのことか | 2年生からの2年間 | 「2年生からの2年間、いちばん力を入れてきたのは◯◯です。」 |
| 将来の答え方 | なりたい職業がある | 「私は将来、◯◯になりたいと考えています。」 |
| きっかけの場 | アルバイトで | 「アルバイト先での◯◯がきっかけです。」 |
| 特色の種類 | 演習 | 「私が特に関心を持ったのは、△△大学の演習「◯◯」です。」 |
| どうしたいか | 身につけたい | 「◯◯を身につけたいからです。」 |
| 力の出どころ | 部活動 | 「部活動で身につけた◯◯は、この仕事でも活かせると考えています。」 |
| 将来の時期 | 5年後 | 「5年後には、◯◯を身につけていたいです。」 |
| 魅力カードの場面 | 職場見学 | 「職場見学に行ったとき、◯◯が印象に残りました。」 |
| 魅力カードの気持ち | おどろいた／見習いたい | 「そのとき私はおどろき、自分も見習いたいと思いました。」 |

## 5. 名詞で答えられないところの逃げ道

「なぜ？」の深掘りだけは、名詞にも文にもなりうる。
そこで**答えの形を見て枠を変える**ようにした。

```
「自分で考えて動ける環境」（名詞止め）→ 「〜環境があるからです。」
「任されたほうが力が出た」（述語）    → 「〜力が出たからです。」
```

魅力カードの観察欄も同じ考え方で、動詞で終わるか名詞で終わるかによって
続く枠を切り替えている。

## 6. 語尾の単調さも直した

名詞から文を組み立てると、どうしても「〜ました。」が並びやすい。
そこで、いくつかの文をわざと体言で受ける形に変えた。

| 前 | 後 |
|---|---|
| 私は◯◯、△△に力を入れてきました。 | ◯◯、いちばん力を入れてきたのは△△です。 |
| その結果、◯◯につながりました。 | ◯◯は、その中で生まれた成果です。 |
| ◯◯の授業「△△」に強く関心を持ちました。 | 私が特に関心を持ったのは、◯◯の授業「△△」です。 |

あわせて、語尾のくり返しチェックを**同じ段落の中だけ**で数えるようにした。
段落が変われば読み手は一度息をつくため、そこまで数えると過剰な警告になる。

これで、進学・就職 × 6テンプレート＝12通りすべてで、
自動チェックの指摘がゼロになった。

## 7. 書き出しチェックも構成に合わせた

「書き出しに志望の話がない」という警告は、
結論から入る型（結論先行型・三つの理由型）でだけ出すようにした。
場面描写型やエピソード型では、体験から入るのが正しいため。

## 8. 型を先に決める（質問と構成をステップに分けた）

以前は「全部の質問に答える → 最後に構成を選ぶ」順だった。
これだと、選んだ構成が使わない材料が余る。将来目標型を選んだのに
「今の自分に足りない力」を答えさせていた、という具合に。
余った材料は字数調整でも削られるため、生徒から見ると「聞かれたのに使われない」設問になる。

そこで順序を逆にした。

```
STEP 0 進路をえらぶ
STEP 1 型をえらぶ      ← 3つの質問で構成を判定
STEP 2〜5 質問に答える  ← その型が必要とする設問だけが出る
STEP 6 組み立てる      ← 集めた材料が、型どおりの順で本文になる
```

設問側には `only: ['future']` のように、出したい型を書く。

| 設問 | 出る型 |
|---|---|
| 将来について／将来の目標／そのきっかけ | 将来目標型 |
| 今の自分に足りないこと（必須） | 成長課題型 |
| その取り組みの結果 | 結論先行型・エピソード型・成長課題型・三つの理由型 |
| そこでできること・特徴 | 結論先行型・将来目標型・場面描写型・三つの理由型 |
| 共感した理念 | 結論先行型・エピソード型・三つの理由型 |

### 余っていた材料も文にした

順序を変えたうえで、それでも使われていなかった回答
（資格・性格・得意なこと・実際に行った場所）にも文の枠を用意した。

| 回答 | 文の枠 |
|---|---|
| 資格・検定 | また、◯◯を取得しています。 |
| 性格 | 自分では「◯◯」「△△」という点が強みだと思っています。 |
| 得意なこと（性格が未記入のとき） | 得意なのは「◯◯」です。／仕事で活かせそうな点は「◯◯」です。 |
| 実際に行った・体験したこと | ◯◯や△△にも参加し、自分の目で確かめました。 |

性格や得意なことは「責任感が強い」（述語）と「国語」（名詞）が混ざるので、
かぎかっこで囲んで「という点」で受け、どちらでも壊れないようにした。
実際に行った場所は、魅力カードの場面や「知ったきっかけ」と重なるものを外し、
同じ話をくり返さないようにしている。

### 段落と段落をつなぐ一文

自分の話から志望先の話へ移るところが急だったので、型ごとに橋を架けた。

| 型 | つなぎの文 |
|---|---|
| エピソード型 | そんな私が◯◯を知ったのは、△△がきっかけでした。 |
| 場面描写型 | あの場面が忘れられず、◯◯について調べるようになりました。 |

どちらも優先度 0（絶対に削らない）にしてある。
このつなぎが消えると、次の段落の「調べるほど」「ここでなら」が
何を指しているのか分からなくなるため。

## 9. 設問の見せ方をつくり直した

答えるのが単語だけになっても、「何をどう書けばいいか」が伝わらなければ手が止まる。
そこで、1つの設問に4つの情報を持たせた。

```
質問       その学校で、いちばん手に入れたいものは何ですか   [必須]
説明       「力」「知識」「技術」などの名前で書きます。
           次の欄で選ぶ言葉とつながって、志望理由の中心になる一文ができます。
こんな書き方  地域の課題を調べる力 ／ 看護の専門知識 ／ 人前で説明する力
注意       「〜したい」まで書くと二重になります。名前だけで止めてください
入力欄     [ 地域の課題を調べる力                    ]
こう文になります
           私が〇〇大学経済学部経済学科を志望した理由は、
           地域の課題を調べる力を身につけたいからです。
```

| 要素 | 役割 | 実装 |
|---|---|---|
| 質問 | 「〜は？」ではなく、話しかける形の文で聞く | `label` |
| 説明 | どう書けば文になるか。1〜2文まで | `hint` |
| こんな書き方 | 2〜4個の例。**押せない見た目**にしてある | `examples` |
| 注意 | よくある失敗を、その場で1行だけ | `avoid` |
| こう文になります | 入力した言葉が本文でどうなるかを、その場で表示 | `preview` |

### 例を押せなくした理由

選択肢のチップと同じ見た目にすると、全員が同じ例を選んでしまう。
このアプリが避けたいのは、まさにそれ。
だから例は破線の枠に薄い文字で置き、「写すもの」ではなく「参考にするもの」にした。

### 「こう文になります」を全設問に付けた

`preview(d)` は回答全体を受け取って、生成側とまったく同じ枠で1文を返す。
魅力カードにしかなかったこの仕組みを、22の設問に広げた。

生徒は文を書かないので、「この単語でいいのか」が自分では判断できない。
書いた瞬間に本文の一文が出れば、その場で言い直せる。
「注意」に書いた失敗も、ほとんどはこれで自分で気づける。

### 魅力カード②には ○ と × を出す

唯一、短い文を書いてもらう欄なので、ここだけは良い例と悪い例を並べた。

```
○ 社員の方が、作業を始める前に必ずおたがいに声をかけ合っていた
× 雰囲気がとても良かった（＝感想だけで、何を見たのか分からない）
```

## 10. 仕上げの2つの整えかた

文を組み上げたあと、本文全体に2つのパスをかけている。

### 2回目からは「貴校」「貴社」で受ける

実際の志望理由書では、学校名を何度も繰り返さない。

```
【前】〇〇大学の演習「…」です。… 同じような学校は他にもありますが、〇〇大学には…
【後】貴校の演習「…」です。…   同じような学校は他にもありますが、貴校には…
```

最初の1回と、結びの段落だけは正式名称のまま残す。
読み手が「どこの話か」を見失わないため、そして
自動チェックの「志望先名が入っているか」も通るようにするため。

### 同じ語尾が続いたら言いかえる

名詞から文を作る以上、「〜と考えています。」が並びやすい。
直前の文と語尾がぶつかったときだけ、意味の変わらない言い方に替える。

| 語尾 | 言いかえ |
|---|---|
| と考えています。 | と思っています。 |
| たいと考えています。 | たいです。 |
| に残りました。 | に残っています。 |

字数を押し出さないよう、**同じ長さか短くなる言いかえ**を優先する。

魅力カードを2枚3枚と書いた人のために、気持ちの文の書き出しも
「そのとき私は」「その様子を見て、私は」「このときも私は」と回している。

## 11. 「それは」が何を指すのか分かるようにした

説明と例を足しても、設問がどこにかかっているのかが分からない問題が残った。

```
【前】将来について、今いえるのはどれですか
      その職業名・分野の名前
      そう思ったきっかけは、どこにありましたか
      そのとき見たこと・経験したこと      ← 「そのとき」がどこを指すのか分からない
```

指示語そのものが悪いわけではなく、**指す先が画面に出ていない**のが原因だった。
そこで3つ手を入れた。

### ① 設問をグループにまとめる

同じ話題の設問を1つの囲みに入れ、番号と見出しをつけた。
囲みの中は全部同じことについての質問だと、見た目で分かる。

| ステップ | グループ |
|---|---|
| 基本情報 | ① あなたのこと ② 志望する学校のこと ③ 書き方の設定 |
| 自分を知る | ① 高校でがんばったこと ② あなたの得意なこと・性格 ③ 将来のこと／これから伸ばしたいこと |
| 学校を知る | ① その学校との出会い ② 心が動いた場面 ③ 調べて分かったこと |
| つなげる | ① 志望理由のひとこと ② この学校でなければならない理由 ③ 入学したあとのこと |

グループの見出しには、そこで何をするのかを1行で書いた。
たとえば「高校でがんばったこと」には
「まず1つ選び、そのことだけを最後まで掘り下げます」と添えてある。

### ② 前の答えを引用する

設問の上に、指す先の答えをそのまま出す。空のあいだは何も出ない。

```
▸ 「課題研究・探究学習」について
その活動に取り組んでいたのは、いつですか          [必須]

▸ 「地域づくり」を目指すきっかけ（自分の体験から）について
そこで見たこと・起きた出来事
```

### ③ 設問名からも指示語を減らす

引用が出ていても、設問名だけで意味が通るほうがよい。

| 前 | 後 |
|---|---|
| それは、いつのことですか | その活動に取り組んでいたのは、いつですか |
| その中での役割（あれば） | その活動での役割（あれば） |
| その中で、自分がやったこと | その活動の中で、自分がやったこと |
| その結果、どうなりましたか | それに取り組んだ結果、どうなりましたか |
| そこから学んだこと | この活動全体をふり返って、学んだこと |
| そのとき見たこと・経験したこと | そこで見たこと・起きた出来事 |
| 実際に行った・体験したこと | その学校について、実際に行った・参加したこと |
| その魅力は、どの種類のものですか | 上のカードに書いた魅力は、どの種類のものですか |

### 順番も入れかえた

先の設問を指してしまっていた2か所を直した。

```
【前】その力は、どこで身につけましたか   ← まだ「その力」が出ていない
      仕事で活かせる、自分の力の名前
【後】その仕事で活かせる、自分の力の名前
      その力は、どこで身につけましたか
```

志望先の特色も、種類を選んでから名前を書く順だったのを、
**名前を書いてから種類を選ぶ**順に変えた。
生徒の頭の中では「あの授業がよかった」が先にあり、
それが「授業」なのか「演習」なのかは後から分類するものだから。

## 12. 設問の見た目をそろえ、個数と字数に上限をつけた

### 全部の設問を同じ形にした

説明・例・注意・プレビューを足していったら、設問ごとに形がばらばらになり、
どこに何があるのか探さないと分からなくなっていた。そこで順序を固定した。

```
▸ 「課題研究・探究学習」について        ← 何についての質問か
Q4   必須              ✓ 入力済       ← 番号・必須か任意か・答えたか
その活動の中で、自分がやったこと          ← 質問（太字）
＋ 書き方のヒント                        ← 説明・例・注意（たためる）
[ 地元商店街での聞き取り調査        ]
                            13 / 30字
こう文になります
その中で、地元商店街での聞き取り調査に取り組みました。
```

番号とバッジを1行目、質問文を2行目に分けてあるので、
質問がどれだけ長くなってもバッジの位置が動かない。

- **Q番号**：ステップの中で通し番号。「あとQ3つ」と数えられる
- **任意のバッジ**：これまで必須にしか印がなく、飛ばしてよいのか分からなかった
- **✓ 入力済**：答えた設問には印がつく。埋め忘れを探すのが速くなる

### ステップの上に進み具合を出した

```
答えた質問 5 / 12問（必須があと1問）          [説明をたたむ]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

「あと何問か」が見えるだけで、途中で投げ出しにくくなる。
必須が全部埋まると、バーが緑に変わる。

### 説明をたためるようにした

慣れてきた生徒には説明が邪魔になる。
右の「説明をたたむ」を押すと、説明・例・注意が
「＋ 書き方のヒント」に折りたたまれ、質問と入力欄だけの画面になる。
この設定はブラウザに保存され、次のステップでも続く。

### 選べる個数に上限をつけた

「2〜3個にしぼると文章がぼやけません」と書いていても、全部押す生徒がいる。
文章に入るのは最大3個なので、押した分が本文に出ないのは不親切だった。

| 設問 | 上限 |
|---|---|
| 高校生活でいちばん時間をかけたこと | 3 |
| 得意なこと／性格 | 各3 |
| 実際に行った・参加したこと | 4 |
| 魅力の種類 | 3 |
| 入学・入社したらやりたいこと | 3 |
| 魅力カードの気持ち | 2 |
| 魅力カードの枚数 | 3 |

上限に達すると、選んでいないチップが押せなくなり、
「3 / 3個」の表示が色を変える。外せば、また選べるようになる。

### 記述欄に字数の上限をつけた

単語で答えてもらう設計なので、長い文が入るとほぼ確実に文が壊れる。
そこで欄ごとに上限を決め、残り字数を出すようにした。

| 欄 | 上限 |
|---|---|
| 役割 | 15字 |
| 手に入れたいもの | 25字 |
| 取り組んだこと・学んだこと・特色など | 30字 |
| 志望先の名前・資格名 | 40字 |
| 魅力カード②（見たこと） | 80字 |
| 魅力カード④（自分とのつながり） | 60字 |
| なぜなぜの各段 | 60字 |

上限に近づくと字数表示が色を変えるので、
「短く言い切る」ほうへ自然に寄っていく。

## 13. どんな書き方をされても文になるようにした

単語で答えてくださいと書いても、実際には述語や丁寧語で書く生徒が必ずいる。

```
【前】effortAction に「毎日メモを取りました」と書かれると
      → その中で、毎日メモを取りましたことに力を注ぎました。
【前】mustPoint に「検査まで自社でやっています」と書かれると
      → 貴社には検査まで自社でやっていますという違いがあります。
```

対策は3つ。

### ① 丁寧語は、枠にはめる前に常体へそろえる

語尾はアプリ側がつけるので、受け取った言葉はいったん常体に戻す。
文体変換の活用表（`toPlainTone`）をそのまま使い回している。
文の途中に埋めるので、「である」ではなく「だ」に寄せる。

```
毎日メモを取りました → 毎日メモを取った → 毎日メモを取ったことに力を注ぎました。
部品を加工します    → 部品を加工する   → 部品を加工するという仕事だと理解しています。
自分から動けません  → 自分から動けない → 私には今、自分から動けないところがあると感じています。
```

### ② 述語で書かれたら、述語用の枠で受ける

| 欄 | 名詞のとき | 述語のとき |
|---|---|---|
| 取り組んだこと | ◯◯に取り組みました。 | ◯◯ことに力を注ぎました。 |
| その結果 | ◯◯は、その中で生まれた成果です。 | ◯◯ことが、その中で生まれた成果です。 |
| 学んだこと | ◯◯を学びました。 | ◯◯ということを学びました。 |
| そこでできること | そこでは◯◯に関わることができると知りました。 | そこでは◯◯ことを知りました。 |
| 仕事の理解 | ◯◯を行う仕事だと理解しています。 | ◯◯という仕事だと理解しています。 |
| まず始めること | まずは◯◯から始めたいです。 | まずは◯◯ことから始めたいです。 |
| 足りない力 | ◯◯が足りないと感じています。 | ◯◯ところがあると感じています。 |
| 将来の姿 | ◯◯を身につけていたいです。 | ◯◯ようになっていたいです。 |

（「仕事がしたいことを目指したい」を防ぐ）

### ③ 述語かどうかの判定を作り直した

以前は語尾1文字（る・つ・い…）で見ていたため、
「手伝い」「あいさつ」まで動詞と判定していた。
語尾のパターンを明示する形に変えて、27件のテストケースを全部通した。

```

人の役に立つ   → 述語      あいさつ           → 名詞
自ら学び、自ら考える → 述語  地元商店街での聞き取り調査 → 名詞
```

### ① 志望先の種類（4択／3択）

「メモ作り」と「手順表」を文字列から見分けるのは無理がある。

### ③ 志望先の特色に「名前」があるか（2択）

## 17. 「読み心地」を数字にして直した

非文はなくなったが、読んで自然かどうかは別の話だった。
そこで7つの項目を数えるものさし（`test/metrics.js`）を作り、
測ってから直し、また測った。

### 測ってみて分かったこと

いちばん重かったのはこれ。

```
同じ回答をした別の生徒どうしで、17文中17文が完全に同じ
```

回答が同じなら文章が似るのは当たり前だが、**1文もちがわない**のはまずい。
このアプリは「その生徒しか書けない文章」を作るためのものなので、
アプリが供給する言い回しが全員共通だと、その目的を自分で壊してしまう。

### 直した5点

**① アプリの言い回しを、生徒ごとに変える**

意味の変わらない言い回しを2〜3通りずつ持たせ、
回答から作ったハッシュで選び分ける。乱数ではないので、
同じ生徒が何度作り直しても同じ文章になる。

```
山田太郎：私が〇〇大学を志望するのは、……からです。
          中でも強く心を引かれたのは、貴学の演習「……」です。
          同じような大学は他にもありますが、貴学には……という違いがあります。

佐藤花子：私が〇〇大学を志望した理由は、……からです。
          とりわけ関心を持ったのは、貴学の演習「……」です。
          ほかにも大学はありますが、貴学にしかない……という点にひかれました。
```

変えているのは、書き出し・特色の受け方・他との違い・打ち込んだこと・
学んだこと・入学後・結び・なぜなぜの受け方・魅力カードの枠など22か所。
魅力カードの枠は「開始位置」をずらすので、1枚目の言い回しも人によって変わる。

はじめは「1つのハッシュ＋場所ごとの数」で選んでいたが、
2人の差が6の倍数になると全部の場所で同じ選択になってしまう。
場所ごとに独立にハッシュを計算する形に変えた。

**② 一文だけの段落を、次の段落につなぐ**

字数調整で文が削られると「同じような学校は……。」が1行だけ残ることがあった。
書き出しと結びは1文でも独立させ、途中の1文段落だけをつなぐ。

**③ 「その中で」の重なりをなくす**

```
【前】その中で、地元商店街での聞き取り調査に取り組みました。
      200人分のアンケート集計と校内発表は、その中で生まれた成果です。
【後】その中で、地元商店街での聞き取り調査に取り組みました。
      200人分のアンケート集計と校内発表が、目に見える形での成果です。
```

**④ 「私」が多いときだけ、外せる主語を落とす**

「私」が4回以上出るときだけ、なくても誰の話か分かる文から落とす。
「私が特に関心を持ったのは」→「特に関心を持ったのは」など。

**⑤ 語尾のくり返しを、文章全体で見る**

これまでは隣り合った文だけを見ていた。
離れていても「〜と考えています。」が4回出れば単調に読める。
また「取り組みたいと考えています」と「活かせると考えています」は
別の語尾に見えて同じ響きなので、まとめて数えるようにした。

### 前後の比較（進路2 × 型6 ＝ 12通りの平均）

| 項目 | 前 | 後 |
|---|---|---|
| 一文だけの段落 | 0.5 | **0.2** |
| 「私」の数 | 4.0 | **3.3** |
| 「その中で」の重なり | 0.7 | **0.3** |
| 同じ語尾の最大連続 | 2.6 | **1.8** |
| 「と考えています」の数 | 2.3 | **1.3** |
| 文頭が「私」 | 1.7 | **1.1** |
| **同じ回答をした別人と同じ文** | **100%** | **43%**（最悪82%） |

### ついでに直した字数調整

言い回しの長さが変わると、字数調整で削られる文も変わる。
その結果、300字の設定で「貴社の技術「〇〇部品の精密加工」です」が
削られ、固有名詞がゼロになる例が出た。

そこで、**同じくらいの長さなら、固有名詞や数字を含まない文から先に削る**
ようにした。志望動機の説得力は具体語そのものなので、
迷ったら具体語のほうを残す。

## 18. 型ごとに、設問セットを作り分けた

`only` で型別に出し分ける仕組みは §8 で入れたが、実際に分かれていたのは
6問だけで、残りは全部の型で同じだった。
そこで「どの型がどの回答を実際に使っているか」を機械的に洗い出した。

```
欄                場面描写 結論先行 エピソード 将来目標 成長課題 三つの理由
effortResult         ×    ○    ○    ×    ○    ○    4/6
featureDetail        ○    ○    ×    ○    ×    ○    4/6
targetPolicy         ×    ○    ○    ×    ×    ○    3/6
futureDream          ×    ×    ×    ○    ×    ×    1/6

attractPoints        ×    ×    ×    ×    ×    ×    0/6  ← 必須なのに全型で未使用
```

### 分かったこと：必須なのに一度も使われない設問があった

「魅力を感じた点（分類）」は必須で聞いていたのに、**6型すべてで本文に
出ていなかった**。魅力カードがないときの代替文でしか使っておらず、
そのカードが必須なので、代替文は永遠に出番がなかった。

直し方は2つあった。設問をなくすか、使うようにするか。
分類そのものは先生がシートで並べ替えるときに役立つので、後者にした。

```
カードがあるとき → 設備・施設や少人数教育といった点にも、特に注目しました。
カードがないとき → 特に設備・施設や少人数教育に心を引かれました。
```

「魅力を感じました」は使い回し表現の判定に引っかかるので避けている。
あわせて、必須ではなく任意に変えた（カードが主役なので）。

### 型ごとに必須を変える仕組み

`requiredIn` と `noteIn` を足した。設問の定義はそのままで、
型に応じて必須かどうかと説明の一言だけが変わる。

```js
{
  id: 'effortResult',
  label: 'それに取り組んだ結果、どうなりましたか',
  only: ['prep', 'story', 'gap', 'three'],
  requiredIn: ['story'],
  noteIn: { story: 'エピソード型は体験が主役なので、ここが文章の山場になります。' }
}
```

| 型 | その型でだけ必須になる設問 |
|---|---|
| 場面描写型 | そこでできること・その特徴 |
| 結論先行型 | そこでできること・その特徴 |
| エピソード型 | 取り組んだ結果／知ったきっかけ |
| 将来目標型 | 目指すようになったきっかけの場 |
| 成長課題型 | （もともと「足りない力」が必須） |
| 三つの理由型 | 共感した理念・校訓の言葉 |

### 型を変える前の答えを、本文に混ぜない

型を変えると、前の型で答えた内容はデータに残る。
それをそのまま生成に渡していたため、

- 聞かれていない「知ったきっかけ」で、行った場所の重複判定がされる
- 答えた覚えのない欄が「まだ本文に入っていない材料」に出る

といったことが起きていた。
生成の入口で**いまの型で聞いている欄だけに絞る**ようにした。

### 画面にも出した

設問ステップの上に、どの型の質問セットかを出す。

```
[将来目標型] に必要な質問だけを出しています              型を変える
```

型をえらぶ画面では、選んだ瞬間に数字が変わる。

```
この型で答える質問：39問（うち必須23問）／目標字数：700字
この型ならではの質問が5問あり、ほかの型では聞く4問はここでは出しません。
聞いたことはすべて本文に使われます。
```

### 検証

型ごとに「質問されるのに本文に一度も出ない欄」を数える検査を回したところ、
**12通り（進路2 × 型6）すべてでゼロ**になった。
（`strengths` は「性格」を書いたときの代替なので対象外）

## 19. 考える順番にステップを並べ直し、芯になる設問を足した

### 4ステップを6ステップに割った

設問ステップが4つで、1つあたり10〜14問あった。
問題は数ではなく、**1つのステップの中で頭の使い方が切り替わる**ことだった。
たとえば「学校を知る」には、思い出す作業（魅力カード）と
調べる作業（特色の名前）が同居していた。

```
【前】基本情報 → 自分を知る → 学校を知る → つなげる
【後】基本情報 → 自分を知る → 思い出す → 調べる → つなげる → その先を書く
        だれが      棚おろし     心が動いた   その裏の    重なりを    着地
        どこへ                   瞬間        中身        見つける
```

- **思い出す**：出会い・行ったこと・魅力カード。調べる前に、感情から入る
- **調べる**：特色の名前と中身。思い出した場面のうしろにあるものを確かめる
- **つなげる**：両方が出そろってから、重なりを探して志望理由の一文にする
- **その先を書く**：入学・入社後と、その先。文章の着地だけに集中する

1ステップあたり3〜13問になり、画面ごとに「いま何を考えるか」が1つになった。

### 足した設問（5問）

文章の質にいちばん効くところを選んだ。

| 設問 | できる文 | 出す型 |
|---|---|---|
| いちばん大変だったこと | いちばん大変だったのは◯◯です。 | 結論先行・エピソード・成長課題・三つの理由 |
| それをどう乗り越えたか | それでも◯◯によって、続けることができました。 | 同上 |
| 大事にしていると気づいたこと | そこから私は、◯◯を大切にするようになりました。 | 全型 |
| そのことをどこで知ったか | このことは、学校案内で知りました。 | 結論先行・場面描写・三つの理由 |
| いずれは誰の役に立ちたいか | いずれは◯◯の役に立てる人になりたいと考えています。 | 全型 |

**「大変だったこと → 乗り越え方」** は、体験の段落を一気に厚くする。
読み手がいちばん知りたいのは、困ったときにどう動く人かという点だから。

**「大事にしていると気づいたこと」** は、この6ステップ構成の要になる設問。
心が動いた場面（思い出す）と、自分ががんばってきたこと（自分を知る）の
両方が画面に出そろったあとで聞くので、答えられる。

```
▸ 心が動いた場面「学生同士が、答えではなく考え方のほうを…」から
あなたが大事にしていると気づいたこと
[ 人と話しながら考えを深めること ]
こう文になります
そこから私は、人と話しながら考えを深めることを大切にするようになりました。
```

この一文は、魅力カードの段落と自分の段落をつなぐ位置に置いている。
1文だけの段落として組み立て、§17 の段落統合で次の段落の頭につながる。

あわせて「活かせる力」を就職だけでなく進学でも聞くようにした
（進学では「ここでの学びにも活かせると考えています。」になる）。

| 結論先行型 | 37問 | 44問 |
| エピソード型 | 37問 | 43問 |
| 将来目標型 | 39問 | 43問 |
| 成長課題型 | 36問 | 42問 |
| 三つの理由型 | 37問 | 44問 |

増えたぶんはステップが増えたことで吸収され、1画面あたりの設問数はむしろ減った。

### ついでに直した

志望先の種類を足したことで「入社後」が「採用後」「就職後」に変わるのに、
自動チェックの「入社後の目標」は `入社|働|仕事|職場|業務` しか見ていなかった。
病院・福祉施設を選んだ生徒が、正しく書いていても指摘される状態だったので、
`入職|採用|就職|勤務` を足した。

## 20. 実際に生徒が作った文章から直した

高校生が実際に作った文章に、6つの不具合が出ていた。
そのままの回答を再現テスト（`test/case1.js`）にして、1つずつ直した。

```
【前】倉庫管理の技術の技術を身につけたいと考えています。
      特に関心を持ったのは、貴社の倉庫作業の管理方法に魅力を感じたという仕事の進め方です。
      自分の落ち着いた雰囲気と合う。
      クラスTシャツの作成係として、デザイン作成を作りました。
      実習で身につけた「学校での培った整理整頓を活かして頑張りたい」という姿勢は、
      この仕事でも活かせると考えています。
      入社後は、先輩からの技術の習得に力を入れたいと思っています。以上が、私が…

【後】倉庫管理の技術を身につけたいと考えています。
      特に関心を持ったのは、貴館の仕事の進め方のうち、倉庫の在庫管理の仕組みという点です。
      自分の落ち着いた雰囲気と合うように感じています。
      クラスTシャツの作成係として、デザイン作成を担当しました。
      実習で得たものを持って、学校で培った整理整頓を活かして頑張りたいと考えています。
      入社後は、先輩からの技術の習得に力を入れたいと考えています。

      これらの理由から、私は…
```

| 不具合 | 原因 | 直し方 |
|---|---|---|
| 技術**の技術** | 選択肢が足す名詞と、入力の末尾が重なった | 選択肢に `dup`（足す名詞）を持たせ、重なるときは名詞を足さない枠に切り替える |
| デザイン**作成を作りました** | 「作ったもの」の枠が、作る系の言葉と重なった | 作成・制作・作り・づくりで終わる語は「◯◯を担当しました」で受ける |
| **に魅力を感じたという**仕事の進め方 | 名前を聞く欄に感想を書かれた | 感想の語尾を落としてから枠にはめ、枠も「◯◯のうち、△△という点です」に変えた |
| 「〜し**たい」という姿勢** | 力の名前を聞く欄に意欲を書かれた | 「〜たい」で終わるときは「◯◯で得たものを持って、〜と考えています」で受ける |
| 常体の**混入** | 魅力カード④の言葉をそのまま使っていた | すでに丁寧なら尊重し、常体なら「〜ように感じています」の枠にはめ直す |
| 結びが前の段落にくっつく | 1文だけの段落を、常に次の段落へ寄せていた | 次が結びのときは、前の段落へ寄せる |
| 点**という点** | 「という点」を足す枠と、入力の末尾が重なった | 点・ところ・こと・違いで終わるときは「という点」を足さない |

### 自動チェックが何も言わなかった

いちばん問題だったのは、**この6つをチェックが1つも拾えなかった**こと。2つ足した。

- **文体の統一**：「です・ます」でも「である」でもない言い切り（「〜と合う。」）を
  どちらにも数えていなかった。文単位で判定し直し、丁寧な語尾を除いてから見る
- **言葉の重なり**（新設）：「技術の技術」のように同じ語が隣り合っていないか。
  「わくわく」「いろいろ」のような重ね言葉は正しい日本語なので、
  漢字を含む語の重なりだけを拾う

### 設問側も直した

不具合の半分は「聞き方が悪くて、想定外の答えが来た」ことが原因だった。

| 設問 | 足した注意 |
|---|---|
| 特色の名前 | 「〜に魅力を感じた」「〜がよかった」のような感想は書きません |
| 活かせる力 | 「〜を活かして頑張りたい」まで書くと文が二重になります。力の名前だけを |
| 大事にしていること | 「会社の雰囲気」のような志望先のよさではなく、あなた自身の行動を |
| なぜ？3回 | 「成長できる」「やりがいがある」は誰にでも当てはまります |

あわせて、志望先の種類に**美術館・図書館などの施設（貴館）**を足した。
美術館あてに「貴社」と書いていたため。

### 足した設問

**入ったあと、どんな場面で働いている／学んでいる自分を思い描きますか**（任意）

```
先輩と一緒に在庫を数えている場面
→ 先輩と一緒に在庫を数えている場面を思い描いています。
```

具体的な絵が浮かぶほど、本気で考えていることが伝わる。
「入社後は◯◯に取り組みたい」だけで終わりがちな段落に、厚みが出る。

## 21. 選んだ活動に合わせて、あとの設問を変えた

STEP 3 の「高校生活で、いちばん時間をかけたことは何ですか」は3つまで選べる。
ところが本文に出てくるのは1つめだけで、続く設問（役割・やったこと・成果・大変だったこと）も
すべて1つめについて聞いているつもりだった。生徒からは、
**3つ選べるのに1つしか聞かれないように見える**ため、
2つめ・3つめの内容を1つめの欄に混ぜて書いてしまう、という誤りが起きていた。

直したのは2点。

### (1) 選んだ活動ごとに答えられるようにした（魅力カードと同じ考え方）

2つめを選ぶと「『アルバイト』では、何をしましたか」、
3つめを選ぶと「『資格・検定の取得』では、何をしましたか」が**増える**。
選んでいなければ出ない。

```js
{
  id: 'effort2Action',
  label: (d) => '「' + effortAt(d, 1) + '」では、何をしましたか',
  showIf: (d) => (d.efforts || []).length >= 2,
  examples: (d) => activityOf(effortAt(d, 1)).action
}
```

`buildSteps(mode, template, data)` が第3引数に回答を受け取り、
`showIf` が false の設問はそもそも作らない。
設問を出し分けるしくみは、型による `only` と同じ経路に乗せてある。

本文には、いちばん詳しく聞いた1つめを主役にしたうえで、
2つめ・3つめを1文にまとめて足す（優先度3＝余裕があれば）。

```
また、アルバイトではレジ打ちに、資格・検定の取得では毎日30分の問題演習にも取り組みました。
```

「行事の企画」（名詞）でも「行事を企画しました」（述語）でも同じ形に受けられるよう、
`isPredicate()` を通して述語なら「〜したこと」に変えてからつなぐ。

### (2) 選んだ活動によって、例と設問文を変えた

「役割」の例が「班長／副キャプテン／実行委員長」と固定だったので、
アルバイトを選んだ生徒にも「班長」が例として出ていた。
17種類の活動それぞれに、役割・やったこと・成果・大変だったことの例を持たせた。

| 選んだもの | 役割の例 | やったことの例 |
|---|---|---|
| 部活動 | 副キャプテン／パートリーダー | 朝練のメニュー作り／後輩への指導 |
| アルバイト | シフトリーダー／新人教育担当 | 混雑時の動き方のメモ作り／レジ締めの確認 |
| 課題研究・探究学習 | 班長／記録係 | 地元商店街での聞き取り調査／アンケートの集計 |
| 資格・検定の取得 | （※役割の設問は例を出さない） | 毎日30分の問題演習／過去問の分析 |

設問文そのものも「『部活動』での役割（あれば）」のように、選んだ言葉を差し込む。
何について聞かれているかが、設問を読むだけで分かる。

そのため設問の `label` / `hint` / `placeholder` / `examples` は、
**文字列だけでなく「回答を受け取って文字列を返す関数」も書けるようにした**。
画面側は `val()` を通して受け取る。

```js
function val(x) { return typeof x === 'function' ? x(state.data) : x; }
```

活動の選び直しで設問ごと入れ替わるため、`efforts` には `rerender: true` を付け、
チップを押したときにその場の描き替えではなく画面全体を作り直す。

## 22. 「選ばせて終わり」だった設問に、場面を書かせた

「得意なこと」「性格」は選択肢を押すだけの設問だった。
そのため出てくる文が、

```
自分では「まじめ」という点が強みだと思っています。
```

で終わってしまう。これは誰が書いても同じ文で、読み手には何も残らない。
選んだ言葉そのものより、**それがどこで働くのか**が読みたいところだった。

そこで、選んだあとに「どんな場面で活かせそうですか」を書く欄を出すようにした。

```
自分では「まじめ」という点が強みで、同じ作業を毎日続けるときに力になれると思います。
得意な「整理整頓」も、部品を決まった場所に戻す作業で役に立つと思います。
```

選択肢を押していないうちは欄が出ない（`showIf`）ので、設問数はむだに増えない。

### 場面のつなぎ方

「場面」の答え方は生徒によってばらばらになる。そこで `sceneAt()` を作った。

| 生徒が書いたもの | 文の中では |
|---|---|
| 後輩に手順を教える場面 | 後輩に手順を教える**場面で** |
| レジが混雑したとき | レジが混雑した**ときに** |
| 締め切りが近いときに | 締め切りが近い**ときに**（助詞の重複を防ぐ） |
| 意見をまとめること | 意見をまとめる**場面で**（「ことの場面」を防ぐ） |
| お客様に声をかけます | お客様に声をかける**場面で**（常体に直す） |
| 品出し | 品出し**の場面で** |

「あいさつ」のような単語を動詞と読みちがえないよう、
かなだけで終わる動詞（「声をかける」）は**助詞を含むこと**を条件に述語あつかいにしている。

この過程で `toPlainTone()` の穴も見つかった。
「朝の準備をします」が「朝の準備をす」になっていた
（「し＋ます」を五段活用と見ていた）。`します→する` を例外に足した。

### 資格・検定は、聞く相手をしぼった

「持っている資格・検定」は全員に聞いていたが、
空欄のまま進む生徒が多く、設問が1つ増えるだけになっていた。
STEP 3 の「いちばん時間をかけたこと」で**「資格・検定の取得」を選んだ生徒にだけ**聞くことにした。

選ばなかった生徒の資格が本文から消えることになるが、
その生徒にとって資格は「いちばん時間をかけたこと」ではないので、
志望動機の中心に置くべき材料でもない、と判断した。

## 23. 必須と任意を、色ではなく形で分けた

「どれが必須か分からない」という指摘があった。
それまでは小さなバッジの**色ちがい**（「必須」＝薄い赤／「任意」＝灰色）だけで分けていた。
10.5pxの2文字は形が似ていて、並ぶと見分けがつかない。

3つの手がかりを重ねた。

| | 必須 | 任意 |
|---|---|---|
| 設問の左の帯 | 実線（3px） | 点線 |
| バッジ | 塗りつぶし＋白抜きの「必須」 | 枠だけの「任意」 |
| 置く場所 | **質問文の後ろ** | 質問文の後ろ |

バッジは質問文の**後ろ**に置いている。
先に置くと「必須」を読んでから質問を読むことになり、
一覧したときに目に入るのが質問ではなくバッジになってしまう。
後ろに置けば、読む順番は「質問 → 必須かどうか」のままになる。

ステップの上には、帯の意味を一度だけ示す凡例を置いた。

```
▍必須 5問    ┊任意 8問
```

入力済の必須は帯が緑に変わるので、
「赤い帯が残っているところが、まだ答えていない必須」と読める。

## 24. 「3つ選んだのに1つしか出ない」を、本当になくした

第21節で2つ目・3つ目の設問を足したが、**本文はまだ1つ目しか出ないことがあった**。
足した文の優先度が3（余裕があれば）だったので、
就職でよくある300〜500字では真っ先に削られていたためである。

数えてみると、こうなっていた。

| 目標字数 | 3つの活動名 | 2つ目の内容 | 性格＋場面 |
|---|---|---|---|
| 300字 | × | × | × |
| 400字 | × | × | × |
| 500字 | × | × | ○ |

設問を足しても、削られるなら答えた意味がない。3つ直した。

### (1) 活動名を、削られない一文に入れた

書き出しの一文（優先度1）そのものを組み替えた。

```
（1つだけ）1年生から3年間、いちばん力を入れてきたのは部活動です。
（3つ選択）1年生から3年間、部活動を中心に、アルバイトや資格・検定の取得にも力を入れてきました。
```

これで**どんな字数でも3つとも必ず本文に出る**。
削られるのは「そこで何をしたか」の詳しい部分だけになる。

### (2) 答えた材料は、優先度を上げる

生徒がわざわざ書いた具体は、一般論より先に入れるべきだと考えた。

```js
pOthers:    (d.effort2Action || d.effort3Action) ? 2 : 3,
pTraits:    d.personalityScene ? 2 : 3,
pStrengths: d.strengthScene ? 2 : 3,
```

「場面まで書いた性格」は具体的な話なので優先度2、
選んだだけの性格は今までどおり優先度3、という切り分けである。

### (3) 長い文を、削れる単位に分けた

「〜に取り組み、〜が身につきました」と1文にまとめていたのを、2文に分けた。

```
アルバイトではレジと品出しに、資格・検定の取得では毎日30分の問題演習にも時間をかけました。（優先度2）
そこで身についたのは、報告・連絡の大切さや毎日少しずつ続けることの力です。（優先度3）
```

字数が苦しいときは後ろだけが落ちる。全部落ちるよりずっとよい。

直したあと：

| 目標字数 | 3つの活動名 | 2つ目の内容 | 性格＋場面 |
|---|---|---|---|
| 300字 | ○ | × | × |
| 400字 | ○ | × | × |
| 500字 | ○ | ○ | ○ |
| 600字 | ○ | ○ | ○ |

300〜400字で削られるぶんは、STEP 8 の「まだ本文に入っていない材料」に出す。
そこに `effort2Action` などを足して、何が落ちたのかが分かるようにした。

## 25. 活動によって、聞く設問そのものを変えた

第21節では、設問の**言葉と例**だけを活動に合わせていた。
設問の並び自体は全員同じだったので、こうなっていた。

```
「資格・検定の取得」での役割（あれば）　　← 役割という考え方がない
「皆勤・無遅刻無欠席」での役割（あれば）　← 同じ
それを、どうやって乗り越えましたか
  例: 朝練習への切り替え／一人ずつ話を聞くこと　← 資格の勉強に朝練習は出てこない
```

3つ直した。

### 役割の設問は、役割のある活動にだけ出す

```js
showIf: (d) => activityOf(effortAt(d, 0)).role.length > 0
```

`role: []` としてある「資格・検定の取得」「勉強・定期考査」「皆勤」「家の手伝い」では、
この設問がそもそも出ない。空欄を見て関係のないことを書き込む余地をなくした。

### 例を、活動ごとに全部そろえた

`ACTIVITY` の各項目に `learned`（学んだこと）と `how`（乗り越え方）を足し、
17の活動すべてで役割・したこと・成果・大変だったこと・乗り越え方・学んだことの
6項目に固有の例が出るようにした。

| 選んだもの | 乗り越え方の例 | 学んだことの例 |
|---|---|---|
| 部活動 | 朝練習への切り替え | 続けることの大切さ |
| 資格・検定の取得 | 苦手分野だけをやり直したこと | 毎日少しずつ続けることの力 |
| アルバイト | 先輩への相談 | 報告・連絡の大切さ |
| 家の手伝い・家業 | 家族と分担を決めたこと | 任される責任の重さ |

### 2つ目・3つ目にも「身についたこと」を聞く

活動名と「したこと」だけでは、選択肢を並べた印象で終わってしまう。
任意の設問を1つずつ足し、書いた人には(3)の一文がつく。

### プレビューは、必ず本物と同じ文にする

設問ごとの「こう文になります」が、生成される文とちがっていては意味がない。
`othersLine()` / `othersLearnedLine()` を questions.js に置き、
生成側の `sEffortOthers()` / `sEffortOthersLearned()` と同じ形を返すようにした。

## 26. 大題を大きくして、まとまりを目で追えるようにした

同じステップに10問以上並ぶと、どこからどこまでが一まとまりなのかが分からなくなる。
大題（「高校でがんばったこと」など）が16pxで、設問の質問文と同じ大きさだったためである。

3つ変えた。

| | 前 | 後 |
|---|---|---|
| 大題の文字 | 16px（質問文と同じ） | 21px（画面が狭いときは18px） |
| 番号 | 22pxの丸 | 30pxの角丸。数字も15pxに |
| まとまりの示し方 | 左に細い線 | 大題の下に2pxの区切り線 |

左の線をやめたのは、必須／任意を示す帯（第23節）と重なって、
どちらの線が何を意味するのか分かりにくかったため。
まとまりは**上の見出し**で、必須かどうかは**設問の左**で、と役割を分けた。

## 27. 打ち込んだことは1つに絞り、「どれ」まで聞くことにした

第21・24節では「3つまで選べる」を前提に、
2つ目・3つ目それぞれの設問と文を用意した。これを取りやめ、**選ぶのは1つだけ**にした。

理由は、3つ選べることが誤答を生む側にまわっていたため。
2つ目・3つ目は一言ずつしか書けないので、
結局は「活動名を並べただけ」の一文にしかならない。
その一文のために設問が4つ増え、どの欄がどの活動の話なのかを取りちがえる人が出る。
志望動機は**1つの経験を深く書いたほうが強い**、というところに立ち返った。

### かわりに「どれ」を聞く

「学校行事」を選んだだけでは、文化祭なのか体育祭なのか修学旅行なのかが分からない。
読み手にとっていちばん知りたいところが抜けたままだった。
そこで、選択のすぐ下に**その名前を書く設問**を足した（必須）。

| 選んだもの | 聞くこと | 例 |
|---|---|---|
| 学校行事 | どの学校行事ですか | 文化祭／体育祭／修学旅行／合唱コンクール |
| 部活動 | 何部の活動ですか | 吹奏楽部／バスケットボール部／野球部 |
| アルバイト | どんなアルバイトですか | コンビニ／飲食店のホール／スーパーの品出し |
| 課題研究・探究学習 | どんなテーマですか | 地元商店街の活性化／高齢者の見守り |
| 勉強・定期考査 | どの教科に、いちばん力を入れましたか | 数学／簿記／英語 |
| 皆勤・無遅刻無欠席 | （聞かない。書くことがない） | — |

### 書いた名前で呼ぶ

活動ごとに「文にどう入れるか」を持たせてあるので、本文の呼び名がそのまま変わる。

```js
'部活動':   { which: { frame: '{X}での活動' } }      → 吹奏楽部での活動
'学校行事': { which: { frame: '{X}' } }              → 文化祭

```

```

1年生から3年間、いちばん力を入れてきたのは吹奏楽部での活動です。

```


### 記述欄でも画面を作り直す

```js
if (field.rerender) {
```

## 28. 得意なこと・性格も1つに絞り、「なぜそれを選んだか」を聞いた

第22節で「活かせる場面」を足したが、選ぶ側は3つまでのままだった。
3つ選ぶと出てくる文はこうなる。

```
自分では「まじめ」「責任感が強い」「協調性がある」という点が強みだと思っています。
```

言葉を並べただけで、どれ一つ裏づけがない。
**1つに絞って、その1つを裏づけたほうが強い**という、第27節と同じ判断をした。

### きっかけの出来事を聞く

選んだあとに出す欄を2つにした。

```
Q  「整理整頓」を選んだのは、どんなことがあったからですか   ← 足したもの
Q  その得意なことは、会社のどんな場面で活かせそうですか
```

聞き方を「〜が得意だと思うのは」ではなく**「〜を選んだのは」**にしてある。
選択肢には「体力がある」のような述語と「整理整頓」のような名詞が混ざっているので、
どちらでも文が壊れない形にした。

### 文の組み立て

きっかけを書いた人は、そこから書き出す。

```
（選んだだけ）自分では「責任感が強い」という点が強みだと思っています。

（きっかけあり）
  任された係を3年間続けた経験から、自分では「責任感が強い」という点が強みだと思っています。
  この強みは、後輩に手順を教える場面で力になれると思います。
  部室の道具置き場を整理したことから、「整理整頓」には自信があります。
  この力は、部品を戻す作業で活かしていきたいです。
```

性格は「〜経験から、」、得意なことは「〜ことから、」で受ける。
2文続くので、同じ言い回しが並ばないよう受け方を分けた。

きっかけの答え方も人によってばらばらなので、`fromEpisode()` で吸収する。

| 生徒が書いたもの | 文の中では |
|---|---|
| 任された係を3年間続けた | 任された係を3年間続けた**経験から、** |
| 毎日の片づけ | 毎日の片づけ**の経験から、** |
| 毎朝いちばんに教室を開けています | 毎朝いちばんに教室を開けている**経験から、**（常体に直す） |
| 部室を整理した経験 | 部室を整理した経験**から、**（「経験」の重複を防ぐ） |

## 29. 使ってもらって出た不具合を3つ直した

### 「やり直す」を押しても、内容が消えなかった

```js
localStorage.removeItem(STORAGE_KEY);
location.reload();
```

これだけでは消えない。`beforeunload` に自動保存をつないでいるので、
**消したあと・再読み込みの直前に、同じ内容が書き戻されていた**。
自動保存のタイマーも同じ理由で書き戻す。先に保存の口をすべて閉じてから消すようにした。

```js
window.removeEventListener('beforeunload', save);
if (saveTimer) clearTimeout(saveTimer);
saveOff = true;               // 読み込み直すまで save() を素通りさせる
localStorage.removeItem(STORAGE_KEY);
location.reload();
```

### 選択肢を押すたびに、画面の先頭へ飛んでいた

選んだ活動によって設問が入れ替わるので、チップを押すと画面全体を作り直している。
その `render()` が毎回 `window.scrollTo(0, 0)` していたため、
選択肢を1つ押すたびに先頭へ戻され、どこを触っていたのか分からなくなっていた。

ステップが変わったときだけ先頭へ戻し、**同じ画面の描き直しでは動かさない**ようにした。
設問が増減して高さが変わるので、位置は「触っていた設問が画面の同じ高さに来る」ように合わせる。

```js
const before = document.querySelector('[data-field="' + anchorId + '"]');
const anchorTop = before && before.getBoundingClientRect().top;
// …描き直し…
window.scrollTo({ top: keepY });
const after = document.querySelector('[data-field="' + anchorId + '"]');
window.scrollTo({ top: window.pageYOffset + (after.getBoundingClientRect().top - anchorTop) });
```

あわせて2つ。
ブラウザ側のスクロール位置調整（scroll anchoring）がこの計算とぶつかるので、
`#view { overflow-anchor: none; }` で止めた。
ステップを変えるときの `behavior: 'smooth'` も、
中身が入れ替わる途中で止まってしまうことがあったため、一気に戻す形にした。

### 言葉づかい

- 「持ち味」→「**強み**」。志望理由書で使い慣れた言い方に合わせた
- 「入力ずみ」→「**入力済**」

## 30. 答えた質問をたたみ、学年・クラス・番号を選ぶ形にした

### 答え終わった設問は1行にたたむ

STEP 3 は設問が15問前後になる。
すべて開いたままだと画面が長く、**まだ答えていないところがどこなのか**が分からない。
答えた設問は「質問＋答え」の1行にたたむようにした。

```
✓  Q1 高校生活で、いちばん時間をかけたことは何ですか
   部活動                                            〔直す〕
```

押せばその場で開く。ステップの上の「答えた質問も表示」で、全部開くこともできる。
この設定は保存されるので、生徒ごとの好みで固定できる。

たたむときに気をつけたのは2点。

**（1）いま触っている設問はたたまない。**
選択肢を押すと画面を作り直すので、押したとたんにその一覧が消えてしまう。
`render(anchorId)` に渡した設問は、答え済みでも開いたままにする。

**（2）初期値が入っているだけの設問はたたまない。**
「それは、どちらに近いですか」のような欄には初期値がある。
answered() だけで判断すると、生徒が一度も見ていない設問が
最初からたたまれてしまう。生徒が自分で触った設問（`state.touched`）と、
初期値と違う値が入っている設問だけをたたむ。

```js
function foldable(f) {
  if (!answered(f)) return false;
  if (state.touched[f.id]) return true;
  if (f.default != null && String(state.data[f.id]) === String(f.default)) return false;
  return true;
}
```

### クラス・出席番号を3つの選択に分けた

「クラス・出席番号」は1つの記述欄で、例に「3年2組 15番」と出していた。
書き方が人によってばらつき、先生が並べ替えるときに困る。

| 前 | 後 |
|---|---|
| クラス・出席番号（記述） | 学年（3通り）／クラス（16通り）／出席番号（50通り）の3つの選択 |

クラスは「1組〜12組」に加えて「A組〜D組」も入れた。
提出用のシートには、3つをまとめた「3年 2組 15番」も従来どおりの列で残している。

前に1行で書いた内容は、`migrate()` で拾えるものだけ移す。
全角数字と漢数字も見るようにしてある。

```
3年2組15番 → 学年=3年 クラス=2組 出席番号=15番
３年２組１５番 → 同上
二年A組8番 → 学年=2年 クラス=A組 出席番号=8番
```

## 31. 魅力カード④を「なぜ」に変え、調べる設問の言い方を直した

### ④「自分のどんな経験と重なりますか」は答えにくかった

ところが生徒からすると、**「重なる経験」を探すこと自体が難しい**。
書きたいのは「なぜそこに心をひかれたのか」なのに、
先に「経験」という形を指定されると手が止まる。

聞き方を変えた。

```
（前）④ 自分のどんな経験と重なりますか
（後）④ そこに心をひかれたのは、なぜですか
      ②で見たことについて、あなたがそう感じた理由を書きます。
      「前に似たことがあったから」でも「自分もこうなりたいと思ったから」でも構いません。
```

経験を書きたい人はそのまま書けるし、
「自分もこうなりたいと思ったから」でよくなったぶん、答えられる幅が広がった。

生成される文も変わる。`cardLink()` は3つの書き方を同じ枠で受ける。

| 生徒が書いたもの | 文の中では |
|---|---|
| アルバイトで声をかけ合うとミスが減ったから | そう感じたのは、アルバイトで声をかけ合うとミスが減った**からです。** |

| 課題研究で、人と話すほど考えが整理された | そう感じたのは、課題研究で、人と話すほど考えが整理された**からです。** |
| 部活動での経験 | そう感じたのは、部活動での経験**があるからです。** |
| チームで動くことの大切さ | そう感じたのは、チームで動くことの大切さ**を知っているからです。** |

あわせて、説明文が就職モードでも「その**学校**でなければならない理由」となっていたのを直した。

### 「いちばん心をひかれたものの名前」

「もの」では何を書けばよいのか分からない。具体を挙げる形に変えた。

```
（前）調べていて、いちばん心をひかれたものの名前
（後・就職）調べていて、いちばん心をひかれた技術・制度・製品などの魅力
（後・進学）調べていて、いちばん心をひかれた学び・制度・施設などの魅力
```

「名前」を落としたぶん、注意書きのほうで
「名前がついていればその名前を、なければ『少人数で進める』のように特徴を書く」と補っている。

## 32. 「調べる」の順番を、答えられる順に組み替えた

「調べる」ステップの1問目が「いちばん心をひかれたものの名前」だった。
名前をいきなり求められると、何を書けばよいのか分からない。
**先に種類を選んでもらえば、次に書くことが決まる**。順番を入れ替えた。

| | 前 | 後 |
|---|---|---|
| Q1 | 心をひかれたものの名前（記述） | **心をひかれたのは、どれですか（選択）** |
| Q2 | 決まった名前がついていますか | **その「◯◯」の名前、または魅力（記述）** |
| Q3 | どの種類のものですか | （なくした。文の形を1つにそろえた） |
| Q4 | そこでできること・その特徴 | **「◯◯」を、なぜ魅力に感じましたか** |

Q1で「研修制度」を選べば、Q2は「その『研修制度』の名前、または魅力」になり、
例も「3か月の新人研修／先輩がつくメンター制度」に入れ替わる。
20種類の選択肢それぞれに例を用意した。

### Q3はなくした。文の形を1つにそろえた

「決まった名前がついていますか」は、生成する文でかぎかっこを付けるかどうかを
決めるためだけの設問だった。聞き方を2度変えても、
**何のために聞かれているのかが生徒に伝わらない**。設問ごとなくし、文の形を1つにした。

```
貴社の〈Q1で選んだ種類〉の〈Q2で書いた言葉〉です。

  貴社の技術の〇〇部品の精密加工です。
  貴社の研修制度の3か月の新人研修です。
  貴学の授業の地域経済フィールドワークです。
```

ただし「少人数で進める」のように述語で書かれると
「〜の少人数で進めるです」になってしまう。そこだけ名詞の形に受け直す。

| 生徒が書いたもの | 文の中では |
|---|---|
| 〇〇部品の精密加工 | 貴社の技術の**〇〇部品の精密加工です。** |
| 安全への意識の高さ | 貴社の職場の体制の**安全への意識の高さです。** |
| 少人数で進める | 貴学の演習の**少人数で進めるという点です。** |
| 少人数で進めます | （常体に直して）**少人数で進めるという点です。** |

生徒からは1つの形にしか見えないので、設問と選択肢と本文がずれようがない。

### Q4は「なぜ魅力に感じたか」にした

「そこでできること・その特徴」では、パンフレットの書き写しで終わってしまう。
読み手が知りたいのは**その生徒がなぜそこにひかれたのか**なので、そこを直接聞くことにした。

```
（前）そこでできること・その特徴
（後）「3か月の新人研修」を、なぜ魅力に感じましたか
```

答え方は人によって変わるので、3つの形で受ける。

| 生徒が書いたもの | 文の中では |
|---|---|
| 若手でも挑戦できるから | 若手でも挑戦できる**という点に、大きな魅力を感じました。** |
| 検査から出荷まで自社でやっているので | （ので→から）〜**という点に、大きな魅力を感じました。** |
| 一人ひとりに合わせて教えてもらえます | （常体に直す）〜**という点に、大きな魅力を感じています。** |
| 安全への意識の高さ | 安全への意識の高さ**という点に、大きな魅力を感じています。** |
| 若手でも挑戦できること | 若手でも挑戦できること**こそ、私が調べていて心を動かされた点です。** |
| だれもが挑戦できる点 | だれもが挑戦できる点**は、ほかにはない魅力だと感じました。** |

いちばん下は、答えが「点」で終わるときに
「点こそ……心を動かされた点です」と同じ言葉が並ばないよう、言い回しを外している。

### 設問・選択肢・生成文を、1つの関数からそろえる

Q3を作り直したあと、**設問の「こう文になります」と本文がちがう**状態になっていた。

```
プレビュー：株式会社〇〇製作所の少人数で進めるという技術です。   ← 古い言い回しのまま
本文　　　：貴社の技術のうち、少人数で進めるという点です。
```

設問側と生成側で別々に文を組み立てていたのが原因。
`featureSentence()` を questions.js に置き、
設問のプレビューはそこから、本文は同じ規則の `sFeature()` から作るようにした。

そのあとQ3自体をなくして形を1つにしたので、
いまはこの関数と `sFeature()` が同じ1行を返すだけになっている。
「安全への意識の高さという点です」のような二重も、この過程で消えた。

### 選択と記述で画面を作り直す

種類を変えたら次の設問の文面と例が変わるので、
選択欄（select）にも `rerender` を効かせるようにした。
これまで記述欄とチップにしか効いていなかった。

Q2に書いた言葉はQ3・Q4が引用するので、Q2にも `rerender` を付けた。
記述欄なので、欄を離れたとき（change）だけ作り直す。

### 「どこで知りましたか」に、親戚・知人を足した

求人票・ホームページ・先生の話…と並べていたが、
高校生が志望先を知るきっかけは、身近な人からの話であることが多い。
「親戚の話」「知人の話」を加えた。

```
このことは、親戚の話で知りました。
```

## 33. ステップの順番を「見た → 調べた → 自分」に変えた

これまでは **自分を知る → 思い出す → 調べる** の順だった。
自分の棚おろしから始めるのは、志望先の話に入る前の助走としては自然に見える。
ところが実際に通してみると、順番が志望動機の組み立て方と合っていなかった。

志望動機は「その志望先で心が動いた場面」が出発点になる。
先に自分の話を書かせると、**志望先と関係のない自己PRを書いてしまう**。
場面を思い出し、その中身を調べたあとなら、
「じゃあ自分のこの経験が活きる」と、志望先に結びつけた形で自分を書ける。

```
（前）基本情報 → 自分を知る → 思い出す → 調べる → つなげる → その先
（後）基本情報 → 思い出す → 調べる → 自分を知る → つなげる → その先
```

「思い出す」「調べる」「自分を知る」の3つは、
どれも他の2つの答えを参照していなかったので、並べ替えても設問は壊れない。

### 番号を書かなくした

入れ替えてみると、画面のあちこちに古い番号が残っていた。

```
「魅力カードがいちばん大事」→ STEP 4（実際は 3）
「提出する」            → STEP 8（実際は 10）
「本文を直しに戻る」ボタン → state.index = 5（調べるへ戻ってしまう）
```

番号をべた書きしていたのが原因。`indexOf('recall')` のように
**画面のIDから引く**ようにした。これで次に並べ替えても、表示もボタンもついてくる。

### さらに「調べる」を先にした

第33節で「思い出す → 調べる」の順にしたが、そのあと2つを入れ替えて
**調べる → 思い出す** にした。

```
基本情報 → 調べる → 思い出す → 自分を知る → つなげる → その先
```

先に志望先の中身を調べておくと、
「あのとき見た場面は、この技術のことだったのか」と結びつけながら魅力カードを書ける。
調べる前に場面だけを思い出すと、印象の記録で止まりやすい。

このときは `views()` の2行を入れ替えるだけで済んだ。
第33節で番号を画面IDから引くようにしておいたので、
画面の説明も「本文を直しに戻る」ボタンも、そのままついてきた。

チェックリストに1か所だけ残っていた「STEP 3 で〜」は、
番号ではなく画面名（「思い出す」の画面）で言うように直した。

### タイトルを「調べる」から「会社を選んだきっかけ」に

「調べる」だと、パンフレットの書き写しをする画面に見えてしまう。
実際に聞いているのは「どこにひかれたのか」なので、その言葉をタイトルにした。

| | 前 | 後 |
|---|---|---|
| 見出し | 会社を調べる／学校を調べる | **会社を選んだきっかけ／学校を選んだきっかけ** |
| タブ | 調べる | きっかけ |
| 説明 | 思い出した場面のうしろにある「中身」を確かめます | まず、その会社のどこにひかれたのかをはっきりさせます |
| 囲みの見出し | 調べて分かったこと | この会社にひかれたところ |

ここで、並べ替えのときに残っていた案内文のずれも見つかった。

```
（調べる）思い出した場面のうしろにある…   ← 「思い出す」はこのあと
（思い出す）調べる前に、まず…             ← 「調べる」はもう終わっている
```

どちらも前後が逆のままだったので、いまの順番に合わせて書き直した。

### ステップの見出しを「何を聞かれているか」に変えた

「調べる」「思い出す」「自分を知る」は、**アプリ側の作業名**だった。
生徒から見ると、その画面で何を答えればよいのかが分からない。
**その画面で答えることそのもの**を見出しにした。

| | 前 | 後 | タブ |
|---|---|---|---|
| STEP 3 | 会社を調べる | 会社を選んだきっかけ | きっかけ |
| STEP 4 | 思い出す | そこに決めた理由 | 理由 |
| STEP 5 | 自分を知る | その会社と自分が合っていると思う理由 | 自分 |

進学のときは「学校を選んだきっかけ」「その学校と自分が合っていると思う理由」になる。

STEP 5 の説明も、棚おろしではなく重なりさがしだと分かる言い方にした。

```
（前）ここから材料集めです。答えるのは単語だけで大丈夫。
（後）ここまで書いた会社の魅力に、自分のどこが重なるのかをさがします。答えるのは単語だけで大丈夫。
```

見出しが長くなったので、画面上部の細い帯だけは1行に収めて「…」で省く。
全文はそのすぐ下のカード見出しに出るので、読めなくなることはない。

### 「その会社との出会い」を、きっかけの画面の先頭へ

「どこで知ったか」「どこまで足を運んだか」は、
魅力カードと同じ画面（そこに決めた理由）に置いていた。
だが**出会いは、ひかれた理由より前の話**である。
「会社を選んだきっかけ」の先頭に移した。

```
STEP 3 会社を選んだきっかけ
   1 その会社との出会い        知ったきっかけ／実際に行った・参加したこと
   2 この会社にひかれたところ  種類 → 名前や魅力 → なぜ魅力に感じたか → どこで知ったか
   ↓
STEP 4 そこに決めた理由
   1 心が動いた場面            魅力カード（この文章の主役）
```

これで STEP 4 は魅力カードだけの画面になり、
「ここがいちばん大事」と言い切れる形になった。

### 「知ったきっかけ」を、全員に聞く1問目にした

`knewBy`（その会社を知ったきっかけ）は、エピソード型でしか聞いていなかった。
だが「会社を選んだきっかけ」という画面の1問目としては、これがいちばん自然な入口になる。
全員に、プルダウンで聞くことにした。

```
その会社を知ったきっかけ　［職場見学 ▼］
  → 株式会社〇〇製作所を知ったのは、職場見学がきっかけでした。
```

これまでこの答えを文にしていたのはエピソード型だけだった（`sBridge`）。
全員に聞く以上、答えが本文に出ないのは困るので、
ほかの5つの型にも `sKnewBy()` を足した（エピソード型は `sBridge` に任せて重複させない）。

### この過程で見つけた2つの不具合

**（1）アプリが、自分のチェックに引っかかる文を作っていた。**
エピソード型の書き出しに「ここで働きたい。」と言い切る形があり、
これが「文体の統一」で**エラー**として検出されていた。
言い切りの勢いは残したいので、かぎかっこで囲んで
`「ここで働きたい」。そう感じたことを、今でもよく覚えています。` に直した。

**（2）本文にあるのに「使われていない材料」に出ていた。**
`usedIn()` が答えをそのままの形で探していたため、
「若手でも挑戦できるから」は本文の「若手でも挑戦できる」と一致せず、
使われているのに未使用として表示されていた。
末尾の「から・ので・ため・こと」を落としてから探すようにした。

あわせて「職場見学で貴社を知りました。」と「このことは、◯◯で知りました。」が
並ぶことがあったので、後者を「◯◯で確かめました。」に変えた。

### 「実際に行ったこと」をやめ、「その職種を選んだ理由」を足した

**やめたもの**：「その会社について、実際に行った・参加したこと」（チップ）。
知ったきっかけ（Q1）と魅力カードの①（どこでのことか）で、
同じことを3回聞いている状態になっていた。生成される文も
「職場見学にも参加し、自分の目で確かめました。」という添え物の一文だけだった。

**足したもの**：「「製造職」を選んだのは、なぜですか」（必須）。
志望動機には「なぜこの会社か」と「なぜこの職種か」の2つの軸がある。
後者を聞いていなかった。基本情報で書いた職種名をそのまま引用して聞く。

置き場所は「仕事の理解」のすぐ前。会社の魅力 → 職種の理由 → 仕事の中身、と流れる。

答え方は人によって変わるので、4つの形で受ける。

| 生徒が書いたもの | 文の中では |
|---|---|
| ものづくりに関わりたいから | 製造職を選んだのは、ものづくりに関わりたい**からです。** |
| 細かい作業が得意なので | 製造職を選んだのは、細かい作業が得意**だからです。**（ので→から、だ を補う） |
| 機械の操作が得意です | （常体に直して）機械の操作が得意**だからです。** |
| ものづくり | 製造職を選んだのは、ものづくり**に関わりたいからです。**（進学は「を学びたいからです」） |

必須の設問なので、生成側の優先度も1（削られない）にしてある。
300字でも6つの型すべてで本文に出ることを確かめた。
