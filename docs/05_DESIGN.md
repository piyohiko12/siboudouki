# UIデザインの考え方

## 1. どう見えるべきか

このアプリを使うのは、進路指導室や教室、あるいは家のスマホで、
**進路について考えている高校生**。だから見た目は次の3つを満たす必要がある。

| 求めるもの | 避けるもの |
|---|---|
| 落ち着いて考えられる静けさ | 派手な色、通知バッジ、急かすUI |
| 「自分ごと」だと感じられること | どの学校でも同じに見える汎用フォーム |
| 書いたものが「作品」に見えること | 入力欄がただ並んでいるだけの画面 |

決めたコンセプトは **「進路指導室の机の上にある、ノートと下敷き」**。
背景にごく薄い方眼を敷き、カードは白い紙、文字は落ち着いた濃紺にした。

## 2. 進路で色が変わる

このアプリでいちばん大きな分岐は「進学か、就職か」。
そこで、**選んだ進路でアプリ全体のアクセント色を変える**ことにした。

| | 色 | 理由 |
|---|---|---|
| 進学 | 藍 `#3558c4` | 学校・学びの色。落ち着いて集中できる |
| 就職 | 深い青緑 `#0e7490` | 働くことの色。藍と明確に見分けがつき、意味色（緑=OK／黄=注意／赤=要修正）とも衝突しない |

実装は `body[data-course]` に CSS カスタムプロパティを載せているだけ。

```css
body[data-course="shushoku"] { --accent: #0e7490; ... }
```

ボタン・チップ・進捗バー・魅力カードの帯まで、`var(--accent)` を参照しているものが
一斉に切り替わる。**「これは自分の進路のアプリだ」と感じてもらうための仕掛け**であって、
装飾ではない。

## 3. 書体を2つ使い分ける

| 用途 | 書体 | ねらい |
|---|---|---|
| UI（ラベル・ボタン・説明） | ゴシック | 読み飛ばしやすく、操作対象だと分かる |
| **生徒が書いた文章**（本文エディタ・魅力カードのプレビュー・提出画面） | **明朝** | 「提出する文書」に見える。清書された実感が出る |

入力欄の中まで明朝にしているのは、書いている最中から
「これは志望理由書だ」と意識してもらうため。行間は 2.15、字間は広めにとった。

## 4. 情報の優先順位を、見た目で表す

### 魅力カードは「主役」に見せる
このアプリの心臓部なので、他の入力欄とは明確に格を変えた。

- 左端に進路色の帯（インデックスカードのタブ）
- ヘッダーに色をつけ、番号と★を置く
- ①②③④の小見出しで手順であることを示す
- 下部に「この文になります」プレビューを**明朝**で表示

### 見直し画面は「直すべきものだけ」を見せる
自動チェックは15項目あるが、生徒が見るべきは赤と黄だけ。
**OKの項目は既定で折りたたむ**ようにした。

```
要修正 0   確認 1   OK 14

［！ 具体性］  数字や固有名詞が見当たりません…

▸ 問題のなかった項目（14件）      ← 畳んである
```

15個の緑の行が並ぶ画面と、「直すのは1つ」と分かる画面では、
生徒が受け取る意味がまったく違う。

## 5. 迷わせない導線

- **ステップの導線**：番号＋短い名前（進路／基本／自分／学校／つなぐ／組立／見直し／提出）。
  現在地は塗り、通過済みは色つきの枠、未到達は淡色。狭い画面では横スクロールし、
  右端をぼかして「まだ先がある」ことを示す。
- **進路未選択のとき**は先のステップへ飛べないようタブを無効化し、「戻る」ボタンも隠す。
- **エラーと案内を混ぜない**。「どちらかを選ぶと、この先の質問が決まります」は
  赤字ではなく淡いグレー。赤は本当に直すべきときだけに取っておく。

## 6. ライトとダーク

`prefers-color-scheme` で全面的に切り替わる。
配色トークンを1か所（`:root`）にまとめてあるので、個別の指定は不要。

気をつけた点：

- ダークではアクセントが明るくなるため、**その上に載る文字色を `--on-accent` で反転**させる
  （白文字のままだとコントラストが足りない）
- `color-scheme: light dark` を指定し、チェックボックスなどのフォーム部品も
  ダークに追従させる（未チェックの白い四角が浮くのを防ぐ）

## 7. 動きは控えめに

- カードは表示時に 10px 下からふわりと上がる（0.38秒）
- 選択時のチェックマークは弾む（0.28秒）
- ボタンは押下で 1px 沈む

いずれも**状態が変わったことを伝えるためだけ**に使い、装飾的なアニメーションは入れていない。
`prefers-reduced-motion: reduce` の環境ではすべて無効化する。

## 8. 触りやすさ・読みやすさ

- タップ対象は最小 38〜46px
- `:focus-visible` にアクセント色のリングを出す（キーボード操作でも迷わない）
- ステップの導線に `aria-current="step"`
- 本文・説明文はすべて行間 1.8 以上
- iPhone の下端（ホームバー）を避けるため、フッターに `env(safe-area-inset-bottom)`

## 9. 印刷

先生に紙で提出する場面を想定し、印刷時は UI を全部消して**文書だけ**を出す。

- 見出しは明朝・字間広め・センタリング・下線
- 氏名と志望先は右寄せ
- 本文は 11.5pt / 行間 2.2 / 両端揃え
- 余白は 14mm × 16mm

## 10. 実装のかたち

CSS は1ファイル（`assets/css/style.css`）。ビルドもフレームワークもない。
先頭にトークン（色・角丸・影・書体）を集約し、以降は用途ごとに16節に分けてある。

```
1. トークン    2. ベース      3. ヘッダー    4. レイアウト
5. 進路選択    6. 入力欄      7. 魅力カード  8. なぜなぜ深掘り
9. 構成選択   10. 本文と字数  11. 見直し     12. プレビューと提出
13. ボタン    14. フッター    15. 狭い画面   16. 印刷
```

色を変えたいときは 1 だけ、余白を変えたいときは 4 だけを見ればよい、という分け方にしている。
