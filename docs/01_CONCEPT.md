# 構想（コンセプト設計）

## 1. 何を作るか

**高校生が、卒業後の進路に向けた「志望動機」を自分の言葉でまとめられるWebアプリ。**

進路は生徒によって違う。だから **最初に「進学」か「就職」かを選び、その先の質問・文章の型・チェック項目をすべて切り替える。**

いきなり原稿用紙に向かうと手が止まる。だから「質問に答える → 材料が集まる → 文章に組み上がる → 見直す」という順に分解する。
最後に回答結果を Google スプレッドシートへ送信し、先生が一覧で確認・添削できるようにする。

## 2. 誰が使うか（ユーザー像）

| 立場 | やりたいこと | このアプリでの体験 |
|---|---|---|
| 生徒（進学希望） | 大学・専門学校の志望理由書を書きたい | 「そこで何を学びたいか」を軸に質問が進む |
| 生徒（就職希望） | 応募書類・面接用の志望動機を作りたい | 「そこでどう働きたいか」を軸に質問が進む |
| 進路指導の先生 | クラス全員の下書きを集めて添削したい | スプレッドシートに1人1行、進路の列つきで集約される |
| 保護者 | 家で一緒に考えたい | スマホでも使え、途中保存できる |

## 3. なぜ進路で分けるのか

同じ「志望動機」でも、進学と就職では見られる点がまるで違う。1つの型で兼用すると、どちらにも中途半端な文章になる。

| | 進学（大学・短大・専門学校） | 就職（企業・公務員） |
|---|---|---|
| 中心に置く問い | そこで**何を学びたいか** | そこで**どう働きたいか** |
| 調べる対象 | カリキュラム・ゼミ・実習・資格 | 事業内容・製品・技術・理念 |
| 必ず必要なもの | 学びたい科目、卒業後の進路 | 仕事内容の理解、自分が活かせる力 |
| きっかけの場 | オープンキャンパス・体験授業 | 求人票・会社説明会・職場見学 |
| 敬称 | 貴校 | 貴社 |
| よくある失敗 | パンフレットの丸写し | 待遇・条件だけが理由になる |
| 共通の失敗 | どちらも「誰でも書ける決まり文句」になりやすい（→ 魅力カードで防ぐ） ||
| 字数の目安 | 500〜800字 | 200〜400字（履歴書欄／ES） |

→ **アプリはこの違いを、設問・生成文・チェック項目の3か所すべてで切り替える。**

## 4. 課題と、アプリでの解き方

| よくあるつまずき | 原因 | 解決策 |
|---|---|---|
| 「何を書けばいいか分からない」 | 白紙から始めている | 質問形式（ワークシート）に分解する |
| 「いい会社／いい学校だと思った」で終わる | 理由の深掘り不足 | 「なぜ？」を3回繰り返す**なぜなぜ深掘り**を組み込む |
| どこにでも通じる内容になる | 相手の研究が浅い | 固有名詞（制度名・製品名）の入力を必須にする |
| 「魅力を感じました」で終わる | 感じたことを一語に圧縮している | **魅力カード**で場面・感情・接続を分けて聞く |
| 決まり文句だけの文章になる | 語彙と観察が足りない | 使い回し表現を自動検出して置き換えを促す |
| 自分の経験と志望先がつながらない | 自己分析と相手研究が別々 | 「つなげる」ステップを独立させる |
| 文章の型が分からない | 構成の知識がない | 3つの質問で6種類の構成から判定し、その型に必要な設問だけを聞く |
| 字数が合わない | 感覚で書いている | 目標字数を超えないよう自動調整＋カウンタ |
| 話し言葉・誤字に気づかない | 自分では気づけない | 自動セルフチェックで警告（進路別の項目つき） |
| 就職で待遇だけを書いてしまう | 何が評価されるか知らない | 「志望理由の中身」チェックで検出して警告 |
| 書きかけで消える | 保存機能がない | localStorage に自動保存 |

## 5. 設計の柱（6つ）

### 柱1: 最初に進路を決める
進学か就職かを選ばないと先へ進めない。ここが決まらないと、質問の内容も文章の型も決まらないため。

### 柱2: 1画面1テーマのステップ形式
全7ステップ。進捗バーで「あとどれくらいか」を可視化し、離脱を防ぐ。

### 柱3: 材料集め → 組み立ての分離
文章を書くのは最後。それまでは「単語・エピソードの断片」を集めるだけでよい、と割り切らせる。

### 柱4: 魅力を「場面・感情・接続」に分けて聞く（魅力カード）
「魅力を感じた点」をチップで選ばせると、全員が同じ一文になる。
「どこで・何を見て・どう感じて・自分の何とつながるか」を分けて聞くことで、
その生徒しか書けない文が必ず生まれる。詳しくは [04_ATTRACTION_CARD.md](04_ATTRACTION_CARD.md)。

### 柱5: 深掘りの強制
「なぜ？」を3段階で聞く。表面的な理由（例：家から近い）から、本質的な動機（例：自分で考えて動ける環境のほうが力を発揮できる）へ降りていく。

### 柱6: 見直しの自動化
提出前に、機械的に判定できることは機械に任せる（字数・文体統一・話し言葉・一文の長さ・志望先名の有無・待遇偏重など）。

### 柱7: 型を先に決める
「質問に全部答えてから構成を選ぶ」と、集めた材料の一部が使われずに余る。
そこで**構成（型）を先に決め、その型が必要とする質問だけを聞く**。
聞かれたことは全部本文に使われるので、生徒から見て回り道がなく、文章の流れも型に最適化される。

型は3つの質問で決める（→ `questions.js` の `PICKER` / `decide()`）。

| 質問 | 効く型 |
|---|---|
| 志望先について、いちばん語れることは？ | 場面がある→場面描写型／中身が明確→結論先行型 |
| 自分について、いちばん語れることは？ | 打ち込んだ活動→エピソード型／将来が明確→将来目標型／挑戦したいこと→挑戦意欲型 |
| どのくらいの長さで書くか | 600字以上→三つの理由型（同時に目標字数も決まる） |

票が同数のときは「その生徒にしか書けない度合い」が高い順
（場面描写 → エピソード → 将来目標 → 成長課題 → 三つの理由 → 結論先行）で決める。
判定はあくまで提案で、生徒はその場で別の型を選び直せる。

## 6. 全体フロー（8ステップ）

```
STEP 0  進路をえらぶ    進学 / 就職 を選択 → ここで全体が切り替わる
   │
STEP 1  型をえらぶ      3つの質問 → 6つの構成から1つを判定（理由つき）＋目標字数
                        ★ ここで決まった型が、この先の設問を出し分ける
   │
STEP 2  基本情報        氏名 / 高校 / 志望先 / 学科・職種 / 入試方式・応募方法 / 目標字数
   │
STEP 3  学校を選んだきっかけ  進学：授業やゼミなどの魅力・受けたい授業・教育目標
        会社を選んだきっかけ  就職：技術や制度などの魅力・仕事の理解・理念
   │
STEP 4  そこに決めた理由  きっかけ・魅力カード
                        ★ 魅力カード＝「どこで・何を見て・どう感じて・なぜひかれたか」
                        ★ 調べて分かった中身を思い浮かべながら、場面を書く
   │
STEP 5  合っていると思う理由  高校でがんばったこと・得意・資格・性格
                        （将来目標型のみ：将来の目標／挑戦意欲型のみ：挑戦したいこと）
   │
STEP 6  つなげる        なぜなぜ深掘り(3段) / ここでなければの理由
                        （就職のみ：自分のどんな力が活かせるか）
   │
STEP 7  その先を書く    入学後・入社後にすること / 卒業後・5年後の姿
   │
STEP 8  組み立てる      STEP 1 の型で下書きを自動生成 → 手直し
                        使われていない材料も表示。型の選び直しもここから戻れる
   │
STEP 9  見直す          自動セルフチェック（進路別） + 手動チェックリスト
   │
STEP 10 提出            スプレッドシートへ送信 / コピー / テキスト保存 / 印刷
```

## 7. システム構成

```
[ブラウザ]                                  [Google]
 index.html
 ├ questions.js  buildSteps(進路, 型) で設問を出し分け
 ├ app.js        画面制御 ─────────────────▶┌─────────────────────┐
 ├ compose.js    生成（語彙表・魅力カード）   │ GAS ウェブアプリ      │
 ├ checklist.js  自動チェック（進路別）       │  doPost(e)          │
 ├ api.js        送信 ────── POST ─────────▶│   ├ トークン照合     │
 └ localStorage  自動保存                    │   ├ 行を追記／上書き  │
                                            │   └ JSON を返す      │
                                            └──────────┬──────────┘
                                                       ▼
                                             Google スプレッドシート
                                             （1提出 = 1行、進路の列つき）
```

- **フロントエンド**: ビルド不要の素の HTML / CSS / JavaScript。GitHub Pages にそのまま置ける。
- **バックエンド**: Google Apps Script のウェブアプリ（`doPost`）。サーバー費用ゼロ。
- **保存先**: Google スプレッドシート。進学・就職を1枚のシートにまとめ、「進路」列で絞り込める。

## 8. 進路の切り替えをどう実装したか

データのキーは進学・就職で**共通**にしてある。

| 共通キー | 進学での意味 | 就職での意味 |
|---|---|---|
| `targetName` | 志望校名 | 志望する会社名 |
| `targetSub` | 学部・学科・コース | 希望する職種 |
| `targetFeature` | その学校ならではの学び・制度 | その会社ならではの製品・技術 |
| `targetPolicy` | 教育理念・求める学生像 | 経営理念・求める人物像 |
| `afterEnter` | 入学後にやりたいこと | 入社後にがんばりたいこと |
| `attractCards` | 学校で見て感じたこと | 会社で見て感じたこと |

進路ごとにしか存在しない設問だけを追加する。

- 進学のみ … `studyWant`（特に学びたい授業）
- 就職のみ … `jobUnderstanding`（仕事の理解）、`contribution`（活かせる力）

文章生成では、語彙表（`LEX`）で呼び方だけを差し替える。

```
入学 ⇄ 入社 ／ 貴校 ⇄ 貴社 ／ 学びたいこと ⇄ 取り組みたい仕事 ／ 学生生活 ⇄ 社会人生活
```

こうすることで、**設問・文章・スプレッドシートの列を1本の仕組みで扱える**。

## 9. スコープ外（今回作らないもの）

- ログイン認証（合言葉トークンのみ。個人情報は最小限）
- AIによる自動添削（テンプレート生成とルールベースのチェックまで）
- 先生用の管理画面（スプレッドシートで代替）
- 面接の想定問答づくり（志望動機の作成までが範囲）
